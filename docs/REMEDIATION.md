# Remediation freeze (binding)

This file is the collection's response to the Ansible community inclusion
review ([ansible-inclusion#89](https://github.com/ansible-collections/ansible-inclusion/discussions/89)
and [forum 46338](https://forum.ansible.com/t/not-to-include-susunola-tencentcloud-collection-in-the-ansible-community-package/46338)).

It is not a roadmap. It is a freeze. CI enforces the quantitative parts
through `scripts/check_remediation_freeze.py`. Raising a ceiling requires a
deliberate edit of `docs/core-allowlist.yml` **and** a justification in the
same pull request. Adding modules, roles, plugins, generated specs, or
sanity-ignore lines without lowering another count is a failed change.

## Status

- Phase: **P3 has landed** (2026-10-28, branch `remediation/p1-surface-reduction`).
  The collection surface is the 77-module / 3-role allowlist; the generator,
  its 502 generated modules, and `plugins/event_source/` are gone. Sanity
  ignores are down to 4 justified entries with 0 forbidden codes, and every
  option description on the allowlist is at least 25 characters.
- Galaxy: no feature release until 2.0.0. 1.4.x is security and defect fixes only.
- Inclusion: do not claim the collection meets community-package requirements
  until the exit criteria in this file are all green.

P1–P3 evidence:

## Why this exists

The published surface is too large to maintain to the community-package bar:

- 1027 modules across 204 product domains
- 502 generated `*_info` modules
- 68 roles
- 34 integration targets
- sanity ignore files still present

Unit-test volume is not evidence. Cloud integration and readable docs are.

## Hard ceilings (ratchet)

`scripts/check_remediation_freeze.py` fails a change that exceeds any of:

| Metric | Current freeze ceiling | 2.0.0 target |
| --- | --- | --- |
| Modules in `plugins/modules/` | 77 (must not rise) | ≤ 120 |
| Modules with the generator banner | 0 (must not rise) | 0 in this collection |
| Roles | 3 (must not rise) | ≤ 3 |
| Inventory + lookup + connection + callback + action + event_source plugins | 12 (must not rise) | ≤ 12 |
| `tests/sanity/ignore-*.txt` entries | 4 per file (must not rise) | 0 forbidden / validate-modules ignores |
| `README.md` lines | 200 (must not rise) | ≤ 200 |

Ceilings only move down.

## 2.0.0 allowlist

The only modules that may remain in `susunola.tencentcloud` after 2.0.0 are
listed in [`docs/core-allowlist.yml`](core-allowlist.yml). Everything else
moves to a separate extras collection that will **not** be offered for
community-package inclusion, or is deleted.

Allowed product domains:

- CAM, CVM, key pairs, VPC, subnet, security group, route table, EIP, NAT
- CLB (ALB stays out of the 2.0 core set until CLB integration is complete
  and a second maintainer exists)
- COS bucket/object/policy, CBS disk/snapshot
- TKE cluster/node pool/addon, TCR instance/namespace/repository
- CDB instance/account, Redis instance
- KMS key, SSM parameter/secret
- Auto Scaling group
- Lighthouse instance/firewall/key pair

Allowed roles after 2.0.0: `tc_vpc_foundation`, `tc_clb_http`, `tc_tke_cluster`.

Forbidden in this collection after 2.0.0:

- any file carrying `# Generated by scripts/generate_info_modules.py`
- `plugins/event_source/`
- dual `api_gateway_*` / `apigateway_*` trees
- entertainment, scanning, sandbox, and other long-tail `_info` modules
  (AME, AMS, ADP, ACP, AGS, Advisor, Anicloud, …)

## Generator freeze

`scripts/generate_info_modules.py` and `scripts/discover_info_specs.py`
were deleted in P1 together with the 502 generated modules. They must not
come back: any file carrying `# Generated by` remains forbidden, and the
freeze guard fails if a generated-banner module reappears.

## Documentation freeze

- Do not regenerate the README catalog tables to advertise module count.
- Do not use module count, product-domain count, or unit-test count as
  inclusion evidence.
- Option descriptions shorter than 25 characters are defects. The 2.0.0
  allowlist must reach zero such options.

## Tests

A write module is not "done" because it has a unit file. After 2.0.0 every
allowlisted write module needs an integration target that covers:

1. check-mode create
2. real create
3. second-run idempotency
4. change one mutable field
5. second-run idempotency
6. check-mode delete
7. real delete
8. immutable-field rejection

No account means no inclusion request.

## Governance

`CODEOWNERS` / `MAINTAINERS.md` listing a single human is a release blocker
for 2.0.0 community-package consideration. A second reviewer with merge
rights has to be named before any new inclusion request.

## Communication

Forum and inclusion replies must be evidence rows:

```text
claim: <reviewer finding>
fix: <commit>
verify: <command>
result: <count>
```

Do not reply with test or module totals.
