▲ 领先项（实测数据）
  • 覆盖面第一梯队：模块总数 834、幂等 write 440、只读 _info 394，均列四家第一（含全腾讯云 2000+ API 的长尾只读覆盖）。
  • 生成式治理：394 个 *_info 由 SDK introspection / spec 生成、禁止手改，幂等 + check mode 全量内置；三类官方库大量模块为半手写维护。
  • 质量门槛：unit + contract 双测试、sanity ignore 预算化（2292/2350 封顶 + CI guard）、coverage gate 80 达成（实测 81.64%），测试密度高于多数官方模块。
▼ 差距项（需追赶）
  • 生态与信任：Galaxy 下载 415 vs 11.9M–90.9M；需持续 release、inclusion 申请（#89 进行中）与社区口碑积累。
  • 集成测试深度：26 targets（77 yml）vs amazon 160（690）/ google 115（468）；13 个旗舰模块中 cvm_instance / vpc / subnet / cdb_instance / tke_cluster 已建专属集成 target（provision → assert → cleanup），其余 8 个（redis_instance / clb_load_balancer / cos_object / scf_function / ckafka_instance / cbs_disk / eip / nat_gateway）尚无专属 target，其中 clb_load_balancer、eip 已被 clb_http / network 场景 target 覆盖，余下 6 个排入 P0-04 路线图（docs/integration-env.md §7）。
  • 读面缺口（首波收口中）：tse / dlc / cos / tdmq 四族 85 个缺口已清零（covered 189 · mapped 41 · 29 判定无 list API 豁免）；余 210 = 181 backlog + 29 no-list（cos 13 / tse 13 / dlc 2 / tke 1），backlog 以 waf 13 / monitor 12 / teo 12 / tsf 11 / config 8 / oceanus 8 居前——写后读不回的闭环随 P0-06+ 逐波收口。
  • 单测广度有虚点：440 个 write 模块中 111 个没有专属单测文件（25%）；81.64% 覆盖率仍由深测模块拉高，广度分布不均。
  • ansible-core 门槛：≥2.19 起步（2.16–2.18 已 EOL；三家 ≥2.16/≥2.17 为历史声明，实际 CI 只测最新版）—— 主动对齐演进，换取旧控制节点用户覆盖的部分代价。
  • 维护资源：个人维护（贡献 / 加入路径见 CONTRIBUTING.md）vs 厂商 + Red Hat/社区全职团队；issue 响应与版本节奏是长期风险。
