单测文件（产物口径）：

插件 + roles：
本库 5 roles（三家官方 0）+ 13 个非模块插件文件（inventory 5 / lookup 2 / connection 1 / callback 1 / event_source 4）；amazon 10 个（action 1 / callback 1 / connection 1 / inventory 2 / lookup 5）。
读图局限：六维归一只能覆盖「有产物可比的量」；幂等质量、生成式治理、零 ignore 这类「质」的领先与「生态下载 0」这类差距不进雷达，见下方结论卡。
Verdict

对比友商：优势与劣势

全部结论基于 Galaxy 产物实测数据（2026-09-02 实拉，非估算）。
▲ 领先项（实测）
  • 覆盖面模块总数 524、幂等 write 313，均列四家第一（azure 426/212 次之）。长尾只读 67 个产品 *_info 由 SDK introspection 自动生成，是三家官方库没有的「全产品可发现」能力。
  • 质量治理生成式治理：200 个 generated 模块由 spec 生成、禁止手改；幂等 + check mode 全量内置。sanity 全绿且零 ignore 豁免（amazon 有 ignore-2.16..2.22.txt 豁免表）。
  • 单测密度345 个单测文件 / 2531 个测试函数；深度 harness 覆盖 run-path + helper + pagination + waiter 时钟路径（批次 1-11 已验证单模块 87-98% 行覆盖）。
  • 组合能力5 个组合 roles（launch / clb_http / web_stack / tke_cluster / disaster_recovery）vs 三家官方 0 个；一次调用编排多资源 + 逆序 teardown。
  • 演进对齐ansible-core 门槛 ≥2.19（2.16-2.18 已 EOL），CI 矩阵 2.19/2.20/2.21 + 每周 devel —— 主动对齐演进而非历史声明。
▼ 差距项（需追赶）
  • 集成测试21 targets vs amazon 160 / google 115（azure 产物无）。且 13 个旗舰模块（cvm_instance / vpc / cdb_instance / redis_instance / tke_cluster / clb_load_balancer / cos_object / scf_function / ckafka_instance / cbs_disk / eip / nat_gateway / subnet）零集成覆盖 —— 旗舰面在真实环境从未被验证。
  • 单测广度313 个 write 模块中 222 个没有专属单测文件（coverage-batching 结构扫描）；覆盖率 60.9% 靠少数深测模块拉高，广度分布不均。
  • 结构补课缺 plugin_utils / action / filter / docsite / extensions.yml 等目录与元数据；doc_fragments 仅 1 个（amazon 5 个）；module_utils 12 个（amazon 42）。文档站点、依赖声明等「官方库标配」尚未建立。
  • 生态信任Galaxy 下载 0 vs 11.8M-90.5M；inclusion #89 尚在评审，暂无第三方采用证据。
  • 维护资源个人维护 vs 厂商 + Red Hat/社区团队；issue 响应与版本节奏是长期风险（缓解：生成式治理 + 自动化 CI 已把人均负担压低）。
⚠ 两条硬真相（自审结论，非客套）： ① 「模块多」不等于「可信」 —— 旗舰模块从未在真实腾讯云环境跑过集成测试，这是向外宣称「企业级」前必须先补的信用账； ② 单测「广度虚胖」 —— 222 个 write 模块零单测，覆盖率 60.9% 由少数深测模块撑起；在补齐前，覆盖率数字对外要保守表述。

Method

口径与方法

所有数字可复现：Galaxy API v3 下载计数 + 发布产物 tar.gz 解包实拉。
1 · 数据来源
Galaxy API v3 download_count（amazon 90,450,498 / azure 16,978,442 / google 11,832,702）+ 各家 tar.gz 解包统计模块 / 测试 / 目录结构。
2 · 模块计数法
总数 = modules/ 下全部 .py；info = *_info.py；write = 总数 − info。azure 官方 426 计数与 Galaxy 页一致。
3 · 测试口径
单测 = unit 目录 test_*.py 文件数；集成 = integration targets 目录数 + yml 数。azure 产物剥离 tests/、google 产物仅 1 个单测文件 —— 已在图中标注，勿当源码水平。
4 · 已知修正
google 集成 504→468（504 是全仓含单测 yml）；集成对比改 target 口径（yml 密度各家不同，直接比 yml 放大 ~11x）；本库 KPI 225 产品 / 87 write。
