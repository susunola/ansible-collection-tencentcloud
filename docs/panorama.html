Verdict

对比友商：优势与劣势

本库按源码 main 实测（2026-09-14，= 已发布 v1.4.0 产物）；对比方按 Galaxy 产物实测数据（版本未变，沿用 09-02 核验口径，下载计数 09-14 实拉）。
▲ 领先项（实测）
  • 覆盖面模块 1005、write 456、info 549，均列四家第一（azure 426/212 次之）。549 个 *_info 中 548 个由 SDK introspection 生成（禁止手改），另 1 个手写（gaap_layer4_listener_info：GAAP 四层监听的列表 API 分为 TCP / UDP 两个 sibling action，生成器无法表达），是三家官方库没有的「全产品可发现」能力。
  • 写读配对v1.1 起系统性关闭 read-surface 缺口：shared resolver 铺到 VPC / TKE / 负载均衡 / 数据库家族，CVM / Lighthouse / database / TCR 读面逐批补齐 —— write 之后能用同一 collection 读回状态的主力产品已闭环。
  • 组合能力68 个 roles（61 个达 solution 成熟度）（含 launch / clb_http / web_stack / tke_cluster / disaster_recovery 等）vs 三家官方 0 个组合 role；一次调用编排多资源 + teardown。
  • 质量治理生成式治理：generated 模块由 spec 生成、禁止手改。许可证头、公共参数文档和等待超时默认值整改后 sanity ignore 债务降至 144 条（36 条 × 4 个 core 版本 ignore 文件）。守卫已由「预算制」改为「棘轮制」：9 类禁止忽略码封顶 0，总条目封顶 144，命中任一禁止码即 CI 失败，每条豁免必须带理由注释，且两个上限都只减不增。coverage gate 80 已达成（09-14 实测 92.65%）。
  • 单测密度1,092 个模块级单测文件 / 10,873 个测试函数（脚本实测）；CI 口径（contract + module_utils + modules）13,902 条：13,716 过 / 186 跳 / 0 xfail（09-25 实测），语句覆盖 92.65%。456 个 write 模块已全部有专属单测文件（09-08 时还缺 111 个）。
  • 演进对齐ansible-core 门槛 ≥2.19（2.16-2.18 已 EOL），CI 矩阵 2.19/2.20/2.21 × py 3.11/3.12/3.13 —— 主动对齐演进而非历史声明。
▼ 差距项（需追赶）
  • 集成测试34 个 target 目录（33 个进 registry，21 个在默认清单）vs amazon 160 / google 115（azure 产物无）。旗舰零覆盖已从 13 个降到 6 个（redis_instance / cos_object / scf_function / ckafka_instance / cbs_disk / nat_gateway）—— cvm_instance / vpc / subnet / cdb_instance / tke_cluster 已立 target，但 billed target 仍未进默认清单；cvm_image / lighthouse 曾是两个孤儿 target（两侧都不在），09-14 已补进 registry 并加「目录 vs registry」反向校验（G1-d 关闭）。
  • 读面缺口112 个 write 模块没有同名 _info，但 backlog 已归零：0 个待补项、0 个 backlog 产品（scripts/gap_backlog.py 实测）：57 个已由 KNOWN_COVERAGE 映射到确实返回该资源的别的 _info（tse 14 / tdmq 13 / dlc 6 等）、55 个资源根本没有列表 API（cos 13 / tse 13 / teo 7），剩下 21 个读面产品全部读得回来。09-14 由 curated TARGETS 一次生成 100 个 _info（读面缺口 226 → 126，backlog 128 → 28）；09-15 再由 13 条 curated target、14 条 KNOWN_COVERAGE 映射与 1 个手写模块（gaap_layer4_listener_info——GAAP 四层监听的列表 API 分为 TCP / UDP 两个 sibling action，生成器无法表达）把最后 28 个收干，backlog 28 → 0、backlog 产品 18 → 0。curated 目标由 scripts/check_info_targets.py --check 双向守住（已进 CI）：目标声明了却没落出 _info 模块或单测、或 spec 带着 1.5.0 标记却无人声明，都会立刻失败；KNOWN_GAPS 现为空集且不再是停车场——新 write 模块必须落地即被覆盖，否则 scripts/audit_info_coverage.py --check 立刻失败。
  • 单测广度write 侧已闭合（456 / 456 全部有专属单测文件，09-08 时缺 111 个）；info 侧 36 个缺口已于 09-14 收口 —— 549 / 549 个 _info 全部有专属单测文件（write 面 456 / 456 亦全）。92.65% 覆盖率仍由深测模块拉高，分布不均。
  • 结构补课plugin_utils（5）/ action（tc_wait）/ filter（tags）/ docsite（Sphinx -W 构建，产物已入库）已补齐，extensions.yml 已落地（声明 plugins/event_source 扩展；09-14 起由 scripts/check_extensions_metadata.py --check 双向校验，声明缺失或指向空目录即失败）；doc_fragments 7 个（amazon 5 个）；module_utils 16 个（amazon 42）。4 个 event_source（cmq/cls/cos/tke）09-14 补齐 EXAMPLES 块与载荷字段文档、修正 2 处永不匹配的规则条件，并由 test_examples.py 双向校验（P1-08 关闭）；ansible-core 与 antsibull-docs 都不识别该扩展类型，docsite 入口仍缺。
  • 生态信任Galaxy 下载 553（09-14 实拉）vs 91.3M / 17.1M / 11.9M；inclusion #89 尚在评审，暂无第三方采用证据。
  • 维护资源个人维护 vs 厂商 + Red Hat/社区团队；issue 响应与版本节奏是长期风险（缓解：生成式治理 + 自动化 CI 已把人均负担压低）。
⚠ 两条硬真相（自审结论，非客套）： ① 「模块多」不等于「可信」 —— 仍有 6 个旗舰模块（redis_instance / cos_object / scf_function / ckafka_instance / cbs_disk / nat_gateway）从未在真实腾讯云环境跑过集成测试，且 billed target 只在人工 dispatch 时才跑：这是向外宣称「企业级」前必须先补的信用账； ② 广度数字要按「写读双闭环」来读 —— 1005 模块里 112 个 write 没有同名 _info（57 个已映射、55 个无列表 API、0 个待补）、132 个产品只有单只读 _info，真正含 write 的产品 71 个；对外展示覆盖时不能只报 1005。

口径与方法

本库数字可复现（源码 main 实测 + pytest 实跑）；对比方数字可复现（Galaxy API + 发布产物 tar.gz 解包统计）。
1 · 数据来源
Galaxy API v3 download_count 09-14 实拉（amazon 91,290,318 / azure 17,127,874 / google 11,900,300 / 本库 553）+ 各家 tar.gz 解包统计模块 / 测试 / 目录结构；本库按源码 main HEAD 实测（= v1.4.0 产物），模块级单测 10,873 个测试函数、CI 口径 13,902 条（13,716 过 / 186 跳 / 0 xfail，09-25 实测；复测命令见本节末）。
2 · 模块计数法
总数 = modules/ 下全部 .py；info = *_info.py；write = 总数 − info。本库 991 = 456 write + 535 info；产品与 roles 来自 scripts/generate_product_capabilities.py（204 产品 / 71 含写 / 68 roles）。
3 · 测试口径
本库单测 = tests/unit 下 test_*.py（1,174 个，其中 1,092 个模块级）；集成 = tests/integration/targets 目录数（34 = 33 进 registry + cleanup 清扫器；2 个孤儿 target 已于 09-14 补登记），默认清单 21 个。覆盖率按 CI 口径实跑：contract + module_utils + modules，--cov=plugins/module_utils --cov=plugins/modules，92.65%。对比方单测 = 其产物 unit 文件数；azure 产物剥离 tests/、google 产物仅 1 个 —— 已标注，勿当源码水平。「测试函数」按模块级 test_*.py 中行首 def test_ 计数，09-14 重新按该口径钉死以防漂移，09-15 起改由 scripts/check_doc_figures.py 实测（25 项数字之一），页面不再手写。CI 条数复测命令：python -m pytest tests/contract tests/unit/plugins/module_utils tests/unit/plugins/modules -q（与 .github/workflows/ci.yml 的 coverage 步同一口径，09-25 实测 13,716 过 / 186 跳 / 0 xfail）。
4 · 已知修正
