# Module tiers

Every module in `plugins/modules/` belongs to exactly one tier. The
assignment is enforced by `scripts/check_module_tiers.py` in CI, so a new
module cannot land without a deliberate tier decision.

| Tier | Meaning | How to recognize | Quality bar |
| --- | --- | --- | --- |
| **core** | Hand-written modules: idempotent write modules and hand-written `*_info` modules the generator cannot express | Listed in `CORE_MODULES` in `scripts/check_module_tiers.py`; no generator marker | Idempotent, check mode, diff output, contract tests, unit tests, full documentation |
| **generated** | `*_info` modules produced from SPECS by `scripts/generate_info_modules.py` | Carries `# Generated by scripts/generate_info_modules.py` | Regenerated, never hand-edited; contract tests via the generator's `_generated_info_builders` |

## Core modules

The write modules are the collection's quality anchor. Each one:

- is idempotent (a second run reports `changed=false`),
- supports check mode (`supports_check_mode=True`, no API write in check mode),
- returns `tc_api_calls` on success and failure (audit trail for the
  `tencentcloud_resource_actions` callback),
- exposes API request IDs on failure,
- is covered by `tests/unit/plugins/modules/` unit tests **and**
  `tests/contract/test_sdk_contracts.py` contract tests against the real SDK.

The hand-written `*_info` modules (e.g. `vpc_info`, `cam_user_info`) stay
core because the generator cannot express their selectors; the bulk
generated `*_info` modules cover the long tail of products instead.

## Generated modules

Generated `_info` modules are produced from two spec sources:

- **curated SPECS** — the literal `SPECS` list in
  `scripts/generate_info_modules.py`, each verified against the official
  API documentation,
- **auto specs** — `scripts/info_specs_auto.py`, written by
  `scripts/discover_info_specs.py` from SDK introspection, with
  `REQUIRED_PARAM_OVERRIDES` fixing the required parameters the SDK cannot
  express.

Never edit a generated module by hand: edit the spec (or the override) and
rerun `python scripts/generate_info_modules.py`.

## Adding a module

1. Decide the tier.
2. Write module (core): implement per the core quality bar, add unit +
   contract coverage, add the name to `CORE_MODULES`.
3. Info module: if the generator can express it, add a spec (curated) or
   let `discover_info_specs.py` nominate it (auto) — no `CORE_MODULES`
   entry needed. Otherwise hand-write it and add it to `CORE_MODULES`.
4. Run `python scripts/check_module_tiers.py --check` and
   `python scripts/sync_registry.py` (updates README tables and
   `meta/runtime.yml` action groups).
