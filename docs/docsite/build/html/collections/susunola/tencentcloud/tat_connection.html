susunola.tencentcloud.tat connection – Execute commands and transfer files on Tencent Cloud instances via TAT

Note

This connection plugin is part of the susunola.tencentcloud collection (version 1.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install susunola.tencentcloud.

To use it in a playbook, specify: susunola.tencentcloud.tat.

New in susunola.tencentcloud 0.12.0

  • Synopsis

  • Parameters

  • Notes

  • Examples

Synopsis

  • Run commands and transfer files on Tencent Cloud CVM and Lighthouse instances through the Tencent Automation Tools (TAT) agent.

  • Requires the tencentcloud-sdk-python-tat package on the controller and the TAT agent running on the target instance.

  • The instance does not need a public IP or a reachable SSH port; only outbound HTTPS from the instance to tat.tencentcloudapi.com is used.

  • Commands run as the TAT agent user, which is root on the standard Linux agent. When privilege escalation (become) is enabled with a different user, the requested user is passed to InvokeCommandRequest.Username.

  • The connection is stateless; every command execution creates a fresh command. Commands are named ansible-tat-<sha1-prefix> so they can be correlated in the TAT console.

Parameters

Parameter

Comments

command_timeout

integer

Per-command timeout in seconds, passed to CreateCommandRequest.Timeout.

Default: 60

command_type

string

Script type passed to CreateCommandRequest.Type.

Use POWERSHELL for Windows targets.

Choices:

  • "SHELL" ← (default)

  • "POWERSHELL"

endpoint

string

Override the Tencent Cloud API endpoint.

Intended for private endpoints, proxies, and integration tests.

string / required

ID of the target instance, e.g. ins-xxxxxxxx (CVM) or lhins-xxxxxxxx (Lighthouse).

Required. Set it with the ansible_tat_instance_id variable or in the play’s connection options.

max_command_chars

integer

Upper bound for a single command payload. Commands (and file transfer chunks) longer than this fail instead of being silently truncated by the API.

Default: 60000

poll_interval

integer

Seconds to wait between DescribeInvocationTasks polls.

Default: 2

poll_timeout

integer

Overall time in seconds to keep polling before failing. Must be larger than command_timeout.

Default: 300

profile

string

added in susunola.tencentcloud 0.5.0

Name of the TCCLI profile section in ~/.tencentcloud/default.configure to read credentials and region from, for example default or prod.

A profile only supplies values not given as module parameters or environment variables; precedence is parameter > environment variable > profile section.

Falls back to TENCENTCLOUD_PROFILE; when neither is set the default section is used.

string

Tencent Cloud region.

Falls back to TENCENTCLOUD_REGION, then to the region key of the selected profile section in ~/.tencentcloud/default.configure.

Notes

Note

  • The TAT API returns at most 64 KiB of output per invocation; longer command output is truncated server-side.

  • Because every command is a fresh TAT command, connection-oriented features that assume an interactive shell (e.g. ``environment`` persistence between commands) are not supported. Set what the command needs inside the command itself.

Examples

- name: Run an ad-hoc command over TAT without a public IP
  hosts: all
  connection: susunola.tencentcloud.tat
  vars:
    ansible_tat_instance_id: ins-xxxxxxxx
    ansible_tat_region: ap-guangzhou
  tasks:
    - ansible.builtin.shell: |
        uptime && df -h / | tail -1

- name: Configure TAT as the default connection in a play
  hosts: tat_hosts
  connection: susunola.tencentcloud.tat
  vars:
    ansible_tat_instance_id: "{{ inventory_hostname }}"
    ansible_tat_command_timeout: 120
    ansible_tat_working_directory: /home/app
  tasks:
    - ansible.builtin.copy:
        src: app.service
        dest: /etc/systemd/system/app.service
    - ansible.builtin.systemd:
        name: app
        state: restarted
