# Contributing

Keep SDK calls in small testable functions and do not log credentials. New
state-changing modules must be idempotent and support check mode where possible.

```bash
ansible-test sanity --docker default
ansible-test units --docker default
ansible-galaxy collection build
```

## Every PR needs a changelog fragment

Add a YAML fragment under `changelogs/fragments/` (see the existing ones for
the format; lint with `antsibull-changelog lint`). CI fails without one, and
the release workflow folds them into `changelogs/` on tag.

## Modules: tiers and contract tests

- `plugins/modules/*_info.py` are **generated** by
  `scripts/generate_info_modules.py` (they carry a `# Generated by` marker).
  Never edit them by hand; edit `scripts/SPECS.py` (or the auto spec) and
  regenerate. `python scripts/generate_info_modules.py --check` verifies they
  are up to date and that every spec is structurally valid.
- Every other module is a **core** module: hand-written and listed in
  `CORE_MODULES` in `scripts/check_module_tiers.py`. A module that is neither
  generated nor listed fails CI (`python scripts/check_module_tiers.py --check`),
  so a hand-written module can never be silently overwritten by the generator.
  See `docs/module_tiers.md`.
- New write modules must register their request builders in
  `tests/contract/test_sdk_contracts.py` (`WRITE_MODULE_BUILDERS` entry plus a
  `test_<module>()` function); the contract suite runs with the real Tencent
  Cloud SDK in CI and fails under the coverage threshold.

## Plugins

- **connection** — a connection plugin (e.g. `tat`) runs without a shell, so
  it must never import Ansible module machinery; reuse `module_utils.client`
  through a thin adapter over the connection options. Document the SDK package
  it needs and add that package to `README.md` requirements.
- **event_source** — Event-Driven Ansible sources implement `async def
  main(queue, args)`; keep blocking SDK calls in `asyncio.to_thread`, resolve
  credentials from args with environment fallbacks, and yield error events
  instead of dying so the source stays alive.
- **inventory** — inventory plugins extend `BaseInventoryPlugin` with
  `Constructable` and `Cacheable`, build their client through
  `module_utils.paging.Paginator`, and declare their options in
  `DOCUMENTATION` with an example YAML file.

## Dependencies

`requirements.txt` pins `tencentcloud-sdk-python` exactly: the committed
`*_info` specs carry a `GENERATED_SDK_VERSION` stamp and
`scripts/check_sdk_drift.py` fails CI when the installed SDK drifts from
it. An SDK upgrade is therefore a deliberate, reviewed change:

1. bump the pin (dependabot opens the PR, or do it by hand),
2. run `scripts/discover_info_specs.py` then
   `scripts/generate_info_modules.py`,
3. review the spec/module diff (new products, changed field names),
4. commit the bump and the regeneration together.

`tencentcloud-sdk-python-tag` and the per-product subpackages whose models
the committed specs reference (`-alb`, `-bdrc`, `-cloudrc`, `-cngw`,
`-fwm`, `-portal`) are pinned in lockstep for reproducible builds; the
`cos-python-sdk-v5` line (only used by the `cos_*` modules) is
intentionally loose.

## Roles

Roles use the `tc_` prefix (e.g. `tc_launch`, `tc_clb_http`). Every role
variable is declared in `defaults/main.yml`, every input the wrapped modules
accept is passed through with `| default(omit, true)`, and each role ships a
`README.md` with a usage example. Roles are covered by the integration targets
that exercise the underlying modules.

## Becoming a maintainer

Active contributors are welcome to become maintainers. See

responsibilities, and how to nominate yourself.

## Releasing

Releases are cut from tags and published by
[`.github/workflows/release.yml`](.github/workflows/release.yml):

1. Bump `version` in `galaxy.yml` and add changelog fragments for the
   changes under `changelogs/fragments/` (lint them with
   `antsibull-changelog lint`).
2. Tag the release and push the tag:

   ```bash
   git tag vX.Y.Z
   git push origin vX.Y.Z
   ```

The workflow runs the sanity/unit tests, lints the changelog fragments,
fails if the tag does not match `galaxy.yml` `version`, folds the
fragments into `changelogs/changelog.yaml` and `changelogs/CHANGELOG.rst`
with `antsibull-changelog release` and commits them back to `main`,
builds the tarball, and creates a GitHub release with the tarball
attached. Publishing to
Ansible Galaxy additionally requires the `GALAXY_API_KEY` repository secret;
without it the publish step is skipped with a warning.
